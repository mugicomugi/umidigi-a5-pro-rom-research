# Windows notes

Tested on Windows 10 Pro 22H2 (build 19045) with Zadig 2.9, platform-tools
37.0.1 and r30.0.5, and mtkclient V2.1.4.

## adb

In booted Android with USB debugging on, `adb` worked without installing any
driver. PID `201d` is a composite device with MTP on interface 0 and ADB on
interface 1.

## fastboot: device works in Device Manager but `fastboot devices` is empty

**Symptom.** In fastboot mode the phone shows up as `Android` with an error.
After installing WinUSB with Zadig it shows as working, but `fastboot devices`
still prints nothing. Trying libusbK instead changes nothing.

**Cause.** `fastboot.exe` finds devices by Google's Android USB
DeviceInterfaceGUID `{F72FE0D4-CBCB-407d-8814-9ED673D0DD6B}`. A normal Zadig
install writes a random GUID into its generated INF, for example
`DeviceGUID = "{1F4CEB82-5EE7-49D1-9CFC-6E7D579CE8BC}"`, so fastboot never sees
the device.

**Fix.**

1. Zadig > Options > List All Devices.
2. Zadig > **Device > Load Preset Device** > [`zadig/fastboot_0e8d_201c.cfg`](../zadig/fastboot_0e8d_201c.cfg).
   The preset sets `GUID = "{F72FE0D4-CBCB-407d-8814-9ED673D0DD6B}"`.
3. Driver WinUSB > Install Driver.
4. **Remove the packages left over from earlier attempts.** On the test PC,
   Windows kept the device bound to an older package with a random GUID even
   after the new one installed successfully. Find them:

   ```powershell
   Get-CimInstance Win32_PnPSignedDriver | Where-Object DeviceID -match "0E8D.*201C" | Select-Object DeviceName, InfName
   ```

   Open each `C:\Windows\INF\oemNN.inf` for `VID_0E8D&PID_201C` (the files are
   UTF-16) and delete every package whose `DeviceGUID` is not the Google one,
   from an elevated prompt:

   ```powershell
   pnputil /delete-driver oemNN.inf /uninstall /force
   ```

5. Replug the phone. The device should now be named `Android Bootloader
   Interface`, and `fastboot devices` lists it.

Dead ends:

- Editing the GUID in a Zadig-extracted INF and running
  `pnputil /add-driver ... /install` fails: the catalog file does not contain
  the hash of the edited file.
- Removing `CatalogFile=` and using Device Manager > Have Disk fails: "The
  third-party INF does not contain digital signature information."

Use the preset instead. Zadig generates and signs the package itself.

## Zadig side effect: trusted root certificates

Every Zadig install adds a self-signed certificate named
`USB\VID_xxxx&PID_xxxx (libwdi autogenerated)` to **both**
`LocalMachine\Root` and `LocalMachine\TrustedPublisher`. That is how its
driver packages get past signature checks. After this project the test PC had
eight of them. List them:

```powershell
Get-ChildItem Cert:\LocalMachine\Root, Cert:\LocalMachine\TrustedPublisher |
  Where-Object Subject -match "libwdi autogenerated" |
  Select-Object PSParentPath, Subject, Thumbprint
```

Remove them with `Remove-Item` from an elevated prompt once you no longer need
the drivers.

## Do not bind WinUSB to the MTP interface

In TWRP, Device Manager listed an `MTP` device with error Code 28. Installing
WinUSB on it with Zadig (package `VID_0E8D&PID_201D&MI_00`) cleared the error
but did **not** fix the TWRP adb push problem. That hardware ID is the MTP
interface of the normal Android composite device, so the binding replaces the
Windows MTP driver for it. Skip this step; if you already did it, remove the
package with `pnputil /delete-driver`.

## mtkclient without UsbDk

mtkclient's Windows instructions recommend UsbDk. **On the test PC, UsbDk was
followed by a Windows crash (see below), and it is not needed.**

1. Clone and install mtkclient's dependencies:

   ```bash
   git clone https://github.com/bkerler/mtkclient
   cd mtkclient
   git checkout cd25cf9c1ff6d36e82697ac2c798e69e9cfb78c3
   pip install -r requirements.txt
   ```

   Without Windows long path support, installing `PySide6`/`shiboken6` fails.
   That package is only for the GUI; `mtk.py` works without it.

2. Get a `libusb-1.0.dll`. `pip install libusb` ships one at
   `site-packages/libusb/_platform/windows/x86_64/libusb-1.0.dll`.

3. Apply [`patches/mtkclient-allow-winusb.patch`](../patches/) and set:

   ```powershell
   $env:MTK_NO_USBDK = "1"
   $env:MTK_LIBUSB_DLL = "C:\path\to\libusb-1.0.dll"
   ```

   Without the patch, mtkclient forces `LIBUSB_OPTION_USE_USBDK` and fails
   immediately with `usb.core.USBError: [Errno None] Other error`.

4. **Pre-install WinUSB for BROM and preloader mode** with Zadig > Device >
   Load Preset Device: [`zadig/brom_0e8d_0003.cfg`](../zadig/brom_0e8d_0003.cfg)
   and [`zadig/preloader_0e8d_2000.cfg`](../zadig/preloader_0e8d_2000.cfg).
   The phone does not need to be connected. BROM mode only lasts a few seconds,
   so it cannot be selected in Zadig by hand.

5. Unplug the phone, run `python mtk.py printgpt`, then hold **Volume Up +
   Volume Down** and plug the cable in.

## UsbDk crashed Windows

- UsbDk 1.0.22 installed from its MSI, then `UsbDkController.exe -n` printed
  `Enumeration failed`. The service was running, and it was registered as
  `UpperFilters` on the whole USB device class
  `{36fc9e60-c465-11cf-8056-444553540000}`, i.e. in the stack of every USB
  device on the machine.
- Shortly after a 656 MB adb transfer, Windows went down with a blue screen.
  The event log shows Kernel-Power 41 with `BugcheckCode 0`, and no minidump was
  written although small dumps were enabled (`CrashDumpEnabled = 3`).

Without a dump this is not proven, but UsbDk was the only third-party kernel
driver added. The patched mtkclient above worked without it. If you installed
it, remove it:

```powershell
msiexec /x {6D4A6ED0-CF41-4615-A4B3-BDA018C3C1CD}
```

or uninstall "UsbDk Runtime Libraries" from Apps, then reboot.
